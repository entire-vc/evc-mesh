RESTClient.CheckoutTask	baseline drift 2026-08-21: evc-mesh's version conditionally omits ttl_minutes from the request body; evc-mesh-mcp always sends it. Behaviorally different, not just refactored. See #3bc9f59d.
RESTClient.ExtendCheckout	baseline drift 2026-08-21: same class as CheckoutTask above (conditional vs unconditional ttl_minutes in the body). See #3bc9f59d.
RESTClient.GetProjectKnowledge	baseline drift 2026-08-21: evc-mesh-mcp added limit/offset/min_importance/tags_any query params; evc-mesh's signature is the old no-params form. See #3bc9f59d.
RESTClient.GetTask	baseline drift 2026-08-21: evc-mesh-mcp resolves short task IDs via /by-short-id/; evc-mesh's copy only ever calls /tasks/<id> and would 404 on a short ID. See #3bc9f59d.
RESTClient.GetTaskDependencies	baseline drift 2026-08-21: evc-mesh-mcp returns a typed *TaskDependencies struct; evc-mesh's copy still hand-parses two legacy JSON shapes into a map. See #3bc9f59d.

RESTClient.UploadArtifact	baseline drift 2026-08-21: THE incident function (#9855f866/#4222c17d lineage). As of evc-mesh-mcp PR #65 (merged 2026-08-21, same day) both sides now do the same checksum/magic-byte validation upstream in handleUploadArtifact — this is pure signature drift now (param order, metadata pre-marshaled string vs map[string]any), not a functional gap. A caller written against one signature will not compile against the other. See #3bc9f59d.
