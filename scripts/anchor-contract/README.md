# Anchor contract

The frontend and the Go server both turn a piece of text into a comment anchor —
the frontend from a mouse selection, the server from a quote an agent sent,
because an agent has no selection to measure. They have to produce the same
anchor for the same words.

When they do not, nothing reports an error. A comment left by an agent and a
comment left by a person, on the same sentence, simply point at different text.
That is the one failure neither implementation can catch on its own, because each
is perfectly self-consistent. This directory is what makes it loud.

| File | What it is |
|---|---|
| `cases.json` | The inputs. A document body, the plain text a reader sees, and the run of it a reader selects. Hand-written — these are the *questions*. |
| `regenerate.sh` | Runs the frontend builder over the cases and writes down its answers. |
| `../../internal/textanchor/testdata/frontend-anchors.json` | Those answers. Generated, never hand-edited. |
| `../../web/src/lib/doc-comments/__tests__/anchor-contract.test.ts` | Frontend half: it still produces them. Also the generator, under `ANCHOR_WRITE=1`. |
| `../../internal/textanchor/contract_test.go` | Server half: it reaches the same offsets from the quote alone. |

Generator and frontend assertion are one file on purpose. Two files would be two
spellings of "run the builder over the cases", and the day they drifted the
fixture would be regenerated by code that is not the code being checked.

## Regenerating

```sh
scripts/anchor-contract/regenerate.sh     # needs web/node_modules — pnpm install in web/
```

Run it after any deliberate change to the resolution rules on either side, and
read the diff as "this is what moved". A table of numbers typed out from reading
the TypeScript would only prove that somebody once typed the two sides to agree;
running the module proves the module produces them.

## What green means, and what it does not

Green means the two implementations agree on every case in `cases.json` — on
Cyrillic, across inline markup, across a soft line break, and on a repeated quote
where only the surrounding context can decide which occurrence was meant. A
one-byte change to any recorded offset reddens both halves.

It does **not** mean the two are equivalent. The contract is a discrimination
test over a fixed set of cases. Add a case when a new class of document turns up
— a table, a footnote, a nested list — because a class with no case in it is a
class where the two are free to disagree.

One case, `ascii-control`, is deliberately unable to prove anything: on ASCII a
byte offset, a character offset and a UTF-16 index are the same number, so it
passes against an implementation using any of them. It is in the set as the
control, and both halves carry an assertion that most cases are *not* like it.
